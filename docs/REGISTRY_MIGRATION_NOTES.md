## What this migration creates

- Schema `private_registry` with 11 tables:
  - `sources`, `source_releases`, `source_artifacts`, `rights_components`, `operation_grants`, `approval_records`, `audit_receipts`, `raw_records`, `import_runs`, `external_mappings`, `findings`
- Constraints: `source_key`/`release_key` regex, `artifact_sha256`/`license_evidence_sha256` `sha256:[0-9a-f]{64}`, `byte_size>0`, `quarantine_path like 'content/quarantine/%'`, `paths_or_fields jsonb_array_length>0`, operation/state enums, territory `en/te/ta`, dates `effective_from<=effective_to`
- Indexes: `source_key`, `source_id`, `artifact_sha256`, `release_id`, `component_id`, `subject_key/digest`, etc.
- RLS: every table `enable row level security`; `revoke all on schema/table from public, anon, authenticated`; deny policies `using (false)` for `anon, authenticated`; `service_role` bypasses RLS (Supabase default).
- Immutability: triggers `trg_prevent_approval_update` and `trg_prevent_release_mutation` enforce append-only `approval_records`/`audit_receipts` and immutable `release_key`/`artifact_sha256`.

Seed: `supabase/seed.sql` — synthetic `source:stepbible:tipnr`/`tvtms` with `candidate` releases, quarantine artifacts, `tipnr-structured-fields` component, `evaluation_import allowed` and `external_ai_processing denied`, synthetic approval `synthetic-rights-reviewer-001`. All digests `sha256: a*64`.

## Forward-fix vs rollback

- **Forward-fix:** Add a new migration `20260914XXXXX_*.sql` (never edit this file). Example: add column via `alter table ... add column ...` with `not null default` to keep existing rows valid.
- **Rollback:** `supabase db reset --to 20260914000001` or checkout prior git commit and `supabase db reset`. No `down` migration is provided; history is immutable. `publication_releases` active-pointer rollback pattern (Task 17) does not apply here — registry rollback is DB reset, not pointer swap.
- **Backup before prod:** `supabase db dump -f supabase/backups/pre-07A-$(date -u +%Y%m%dT%H%M%SZ).sql` (local) or Supabase Dashboard → Database → Backups (hosted).

## RLS verification

Test `supabase/tests/01_private_registry_rls_test.sql` checks:

1. `pg_class.relrowsecurity = true` for all 11 tables
2. Zero grants to `anon`/`authenticated` on `private_registry.*` (`information_schema.role_table_grants`)
3. `pg_policies` deny policies exist
4. Append-only trigger exists
5. Invalid `sha256` and bad `quarantine_path` are rejected (check violations)
6. `unknown` state permitted in DB but denied by evaluator `packages/content-schema/src/registry.ts:84` (fail-closed)

Manual check after `supabase start`:

```sql
set role anon; select * from private_registry.sources; -- must be denied (0 rows or permission denied)
set role authenticated; insert into private_registry.sources ... -- must be denied
reset role; -- service_role / postgres can read
```
