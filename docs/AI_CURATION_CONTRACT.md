# AI_CURATION_CONTRACT

Status
DRAFT NORMATIVE CONTRACT - NOT YET IMPLEMENTED
Al output is untrusted draft data. Al cannot approve, publish, create rights permissions, or write
database rows. This contract is versioned independently from Postgres and SQLite; deterministic
converters connect them.
Normative words MUST，MUST NOT，and SHoULD carry their ordinary specification meanings.

Three artifacts

system-created curation job manifest
AI draft package I
reviewed publication package generated by the pipeline
The job constrains what the agent may see and produce. The draft uses semantic stable keys. The
publication package contains trusted IDs, hashes, derived spans, release metadata, and approvals.

Trust rules
AI MUST:
• Return strict JSON or atomic NDJSON conforming to the requested schema and vocabulary versions
Use review_status: "draft"
Reference only supplied stable canon, scope, entity, edition, and approved-source keys
Put uncertainty in typed fields and unresolved matters in open_questions
• Express substantive assertions as claims with citations
· Copy only bounded exact selectors from Scripture supplied in the immutable job snapshot
AI MUST NOT generate:
• Composed, corrected, paraphrased, or translated Scripture; licenses, permissions, approval
identities, or publication state
Database UUlDs/foreign keys, trusted timestamps, hashes, offsets, counts, or checksums
Geographic coordinates or source locators not present in supplied evidence
New canonical keys for unresolved identities
New entity candidates use job-local keys and enter resolution quarantine. Source candidates are
prohibited in contract v1.

Validation pipeline

Perform no database mutations until all pre-import gates pass:

safe parse and duplicate-key rejection
-> schema and size/depth limits
-> schema/vocabulary/job/input-snapshot binding
-> canon/reference/scope checks
-> stable-key and candidate resolution
-> translation-edition/reference mapping
-> mention selector and Unicode validation
-> claim/citation/source checks
-> chronology/geography/perspective checks
-> localization and fallback checks
-> rights checks
-> duplicate/contradiction/cross-record checks
-> reviewer-readiness report

Validation emits structured findings with code, severity, stage, record key, JSON pointer, safe
message, expected/actual, and remediation. Warnings cannot downgrade publication blockers.
Representative errors include unknown entity/source, unresolved candidate, missing citation,
edition mismatch, ambiguous mention, grapheme split, overlap conflict, invalid range, precision
exceeding evidence, locale mismatch, Al approval attempt, rights unknown/denied, revision conflict,
and unsupported field/version.

Idempotent import and immutable publication
Canonicalize parsed JSON with RFC 8785/JCS before SHA-256; retain a separate raw-output digest
Unique draft identity is package key plus draft revision
Same identity/digest is an idempotent no-op
Same identity with a different digest is rejected
Changed content increments draft revision
Parse/validate/resolve completely before an atomic staging transaction
Store source-to-row lineage and keep drafts private
Approval binds authenticated human decisions to the exact digest
Any change invalidates approval
Pinned converters generate immutable release packages and a dry-run semantic diff

The system owns submission ID, attempt ID, revision allocation, server time, and canonical digest.
Parallel jobs produce distinct submissions; they never compete for an Al-chosen revision. Human
approval binds the canonical payload digest, while the raw digest remains audit lineage.
Normative system artifact schemas are required for the input-bundle item manifest, generation
receipt, validation report, review decision, approval receipt, publication manifest/member/
dependency, import result, release activation, SQLite projection, and rollback. Authenticated
append-only server records provide authorization; a bare hash is not a signature or proof of actor.

Security and privacy
Treat Al output, retrieved pages, and source excerpts as hostile data
· Delimit sources so their instructions cannot control the agent
Default to no arbitrary network access and record allowed fetches/digests
Never dereference an Al-generated URL or filesystem path
Reject duplicate JSON keys, control characters, traversal, HTML/script payloads, excessive 1
nesting, oversized strings/files, and decompression bombs
Store raw output in restricted quarantine and keep it out of ordinary logs
Use parameterized SQL and typed converters
Never prompt with secrets, private reviewer data, or unapproved licensed material
Enforce cost/rate/concurrency limits
Public clients cannot read drafts or mutate reviews
Rights statements from Al are candidates only; missing rights fail closed
Store structured outputs and audit receipts, never hidden chain-of-thought

Task: produce exactly one <package-kind> document for <scope>.
Contract: schema <version>; vocabulary <version>.
Inputs: use only the supplied Scripture snapshot, entity catalog, source catalog, and policies.
Identity: reference supplied stable keys; put new candidates under candidate:<job-id>:<local-key>.

Unknowns: use null and open_questions; never guess.
